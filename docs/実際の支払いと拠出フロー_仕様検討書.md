# 実際の支払いと拠出フロー 仕様検討書

## 1. 文書の位置づけ

家賃や光熱費などの共通支出を、夫婦それぞれのどちらの口座から実際に支払うかを可視化し、収入に応じた負担割合との差を調整する新規画面の検討資料です。

この文書は仕様確定前の検討案です。画面・データ・計算方法は、未決事項の合意後に確定します。既存の家計負担割合計算画面の仕様を変更するものではありません。

## 2. 背景と目的

現在の計算画面は、共通予算の合計に夫婦それぞれの収入割合を適用して、目標となる負担額を表示します。一方、実際の家計では、家賃や光熱費などが一方の口座から引き落とされることがあります。そのため、画面上の負担額と、各自の口座から実際に出ていく金額が一致しない場合があります。

新規画面では、次の2つを分けて表示することを目指します。

1. **目標負担額**：従来どおり、収入に応じた負担割合から算出する金額
2. **実際の支払額**：各予算項目を、夫・妻のどちらが支払う設定かに基づく金額

この2つの差額を示し、どちらからどちらへいくら拠出・精算すれば、実際の負担が目標負担額に近づくかを調整できるようにします。

## 3. 用語

| 用語 | 意味 |
| --- | --- |
| 負担割合 | 夫婦それぞれの手取り収入が合計収入に占める割合 |
| 目標負担額 | 共通予算合計に負担割合を適用した金額 |
| 支払担当 | 各予算項目の代金を実際に支払う人として画面上で選択した夫または妻 |
| 実際の支払額 | 支払担当に割り当てられた予算項目の金額の合計 |
| 拠出調整額 | 目標負担額と実際の支払額の差を埋めるための、夫婦間の移動額 |

## 4. 対象範囲の案

### 対象に含める案

- 現在の手取り月収と共通予算を使って計算する。
- 予算項目ごとに、支払担当を「夫」または「妻」から選択できる。
- 各人の目標負担額、実際の支払額、差額を表示する。
- 差額から、どちらからどちらへいくら移動すればよいかを表示する。
- 入力や支払担当の変更に応じて、金額と図を即時更新する。
- 現在の計算画面・ボーナス計算画面とは独立した画面として追加する。

### 対象外とする案

- 銀行口座への接続、口座番号・認証情報の取得、実際の振込や自動引き落とし。
- 銀行明細との照合、支払実績の自動取り込み。
- 夫婦間での合意や公平性そのものの判定。
- 収入比例以外の負担割合ルールの新設。

## 5. 画面構成の案

1. **収入と負担割合**
   夫婦それぞれの手取り月収、合計、負担割合を表示する。既存画面の入力と連動させるか、新規画面内に独立した入力欄を持つかは未決。

2. **支出と支払担当**
   共通予算を項目別に一覧表示する。各項目の金額と支払担当を確認・変更できるようにする。共通予算の項目・合計は既存画面と同じデータを使う。

3. **お金の流れ**
   夫・妻それぞれから共通支出へ向かう金額を可視化する。支払担当別の実際の支払額と、負担割合から求めた目標負担額の違いを色やラベルでも区別する。色だけに意味を持たせない。

4. **拠出調整**
   調整が必要な場合は、送金元・送金先・金額を一文で表示する。調整不要の場合は「追加の拠出調整はありません」と表示する。

5. **負担後の残額**
   目標負担額を収入から差し引いた残額を表示する。必要に応じて、実際の支払額を差し引いた時点の手元残額も併記し、精算前後の違いを確認できるようにする。

## 6. 計算方法の案

### 6.1 目標負担額

既存画面と同じ収入比例の計算を用います。

```text
合計収入 = 夫の手取り収入 + 妻の手取り収入
夫の負担割合 = 夫の手取り収入 ÷ 合計収入
妻の負担割合 = 妻の手取り収入 ÷ 合計収入
夫の目標負担額 = 共通予算合計 × 夫の負担割合（円単位で四捨五入）
妻の目標負担額 = 共通予算合計 - 夫の目標負担額
```

合計収入が0円の場合は、既存画面と同様に負担割合・目標負担額を0円とする案です。

### 6.2 実際の支払額

各項目の金額を支払担当別に合計します。

```text
夫の実際の支払額 = 支払担当が夫である項目の金額合計
妻の実際の支払額 = 支払担当が妻である項目の金額合計
```

### 6.3 拠出調整額

```text
夫の差額 = 夫の目標負担額 - 夫の実際の支払額
妻の差額 = 妻の目標負担額 - 妻の実際の支払額
```

一方の差額がプラス、もう一方がマイナスの場合、プラスの人からマイナスの人へ、差額の絶対値を移動すれば目標負担額に一致します。支払担当が夫婦のいずれかに割り当てられ、全項目が同一の共通予算を構成している場合、夫婦の差額の合計は0円になります。差額の符号を画面上で説明し、送金方向を取り違えない表示にします。

### 6.4 計算例

既存仕様書記載の共通予算299,000円、夫の収入240,000円、妻の収入210,000円を例にします。各予算項目の支払担当を割り当てた結果、夫が家賃90,000円と光熱費等を含む合計150,000円、妻が残り149,000円を支払う設定だったとします。

| 項目 | 夫 | 妻 |
| --- | ---: | ---: |
| 負担割合（表示上の概数） | 53.3% | 46.7% |
| 目標負担額 | 159,467円 | 139,533円 |
| 実際の支払額 | 150,000円 | 149,000円 |
| 差額（目標 - 実際） | +9,467円 | -9,467円 |

この場合は、夫から妻へ9,467円を拠出・精算すると、最終負担額が目標負担額に一致します。実装時には項目割り当てから支払額を計算し、手入力の例示額は使用しません。

## 7. 操作の流れの案

1. 収入と共通予算を確認する。
2. 各項目の支払担当を、実際の引き落とし・支払いに合わせて選ぶ。
3. 各人の実際の支払額と目標負担額を比較する。
4. 表示された調整額を参考に、夫婦間の拠出・精算を検討する。
5. 支払担当や予算額を変更し、調整結果を確認する。

画面が提示する金額は計算上の提案であり、実際に送金するかどうかは利用者が判断します。

## 8. 入力・例外時の扱いの案

- 収入・予算金額は0円未満を受け付けない。
- 支払担当が未設定の項目を許容するか、初期値をどちらかにするかは未決。未設定を許容する場合、その項目を支払額に含めず、未割当額を明示する。
- 合計収入が0円の場合でも、支払担当と実際の支払額は表示する。目標負担額を0円とした結果、調整額が全額一方から他方へ向く場合は、誤解を招かない注記が必要。
- 片方の収入が0円の場合は、既存画面と同じく収入比例ではもう一方が100%負担となる。
- すべての項目が割り当てられていない場合、未割当額を含めて差額計算が成立するか、調整額の表示を保留するかを定義する。
- 予算金額を変更した場合、支払担当別の実際の支払額と拠出調整額を直ちに再計算する。

## 9. データ・画面連携の案

- 現在の共通予算マスタは `public/data/budget_data.csv` で管理され、列は `category`, `item`, `amount`, `is_active` です。支払担当をCSVに追加するか、画面内の設定として持つかは未決です。
- 現在の計算画面での予算編集は表示中のみ有効です。新規画面の収入・金額・支払担当も同様に一時的な編集とするか、ブラウザーに保存するかは未決です。
- 既存の計算画面と入力状態を共有する場合、画面間の値の同期方法を設計する必要があります。初期版では独立した画面状態にする案もあります。
- 口座名・口座番号などの金融情報は扱わず、支払担当は夫・妻の区別に限定する案です。

## 10. 未決事項

実装着手前に、少なくとも次の点を決めます。

1. **支払担当の粒度**：項目ごとに「夫・妻」を割り当てるか、実際の支払額を人ごとに直接入力するか。
2. **共通口座の扱い**：夫婦いずれかの口座だけを対象とするか、共通口座への各自の入金も表示するか。共通口座を対象に含める場合、口座からの支払いと口座への拠出を二重計上しないルールが必要。
3. **拠出調整の意味**：支払者への立替精算として表示するか、共通口座へ事前に入金する金額として表示するか。両方を扱う場合の切替方法。
4. **初期画面状態**：支払担当の初期値を設定するか、未割当で開始するか。
5. **入力値の共有**：既存画面と収入・予算の値を共有するか、独立して入力するか。
6. **保存方法**：画面を閉じた後も設定を保持するか、現在の計算画面と同様に再読み込みで初期状態へ戻すか。
7. **精算の時点**：月末の精算額のみを示すか、月初の共通口座への拠出額も扱うか。
8. **未割当・不足時の表示**：未割当項目や目標負担額に届かない予算・支払設定を、どのように警告するか。

## 11. 仕様確定時の確認事項

- 夫婦間の差額移動後に、最終的な各人の負担額が目標負担額と一致すること。
- 端数処理を含めて、夫婦の目標負担額の合計が共通予算合計と一致すること。
- 全項目を割り当てた場合、実際の支払額合計が共通予算合計と一致すること。
- 送金元・送金先の表示が、差額の正負と一貫していること。
- 収入0円、片方の収入0円、予算0円、未割当項目などのケースを確認すること。
- 既存の計算画面・ボーナス計算画面の動作と表示に影響を与えないこと。
