# ボーナス用計算ページ 検討資料

## 1. 目的

夫婦それぞれのボーナス手取り額と、世帯で決めた貯金目標額を入力し、目標額を負担割合に応じて夫婦で拠出した場合の負担額と拠出後の残額を確認できるページを追加する。

月々の共通予算ではなく、ボーナスから貯金に回す金額を計算する。入力値を変更すると結果がすぐに更新される想定。

## 2. 想定する画面

- URL は `/bonus` とする案。
- 既存の月次計算ページとは独立した画面とし、ヘッダーから相互に移動できるようにする。
- 入力項目：
  - 夫のボーナス手取り額
  - 妻のボーナス手取り額
  - 世帯の貯金目標額
- 計算結果：
  - 夫婦それぞれの負担割合
  - 夫婦それぞれの貯金拠出額
  - 拠出後のボーナス残額
  - 世帯の拠出額合計と拠出後残額合計

## 3. 計算案

負担割合は入力されたボーナス手取り額の比率とする。貯金目標額をこの割合で分け、夫の拠出額を円単位で四捨五入する。妻の拠出額は目標額から夫の拠出額を引いて求め、2人の拠出額の合計が常に目標額と一致するようにする。

```
ボーナス合計 = 夫のボーナス手取り額 + 妻のボーナス手取り額
夫の負担割合 = 夫のボーナス手取り額 ÷ ボーナス合計
妻の負担割合 = 妻のボーナス手取り額 ÷ ボーナス合計

夫の拠出額 = 貯金目標額 × 夫の負担割合（円単位で四捨五入）
妻の拠出額 = 貯金目標額 - 夫の拠出額

夫の拠出後残額 = 夫のボーナス手取り額 - 夫の拠出額
妻の拠出後残額 = 妻のボーナス手取り額 - 妻の拠出額
世帯の拠出後残額 = ボーナス合計 - 貯金目標額
```

この方式では、目標額がボーナス合計を上回る場合、どちらかまたは両方の拠出後残額がマイナスになる。実際の資金不足を見落とさないよう、マイナス額を表示する案。

## 4. 初期値の案

動作イメージを確認するための仮の初期値。将来的に利用者が自由に変更でき、初期値は仕様確定時に調整できる。

| 入力 | 仮の初期値 |
| --- | ---: |
| 夫のボーナス手取り額 | 500,000円 |
| 妻のボーナス手取り額 | 400,000円 |
| 貯金目標額 | 300,000円 |

この例では、夫の負担割合は約55.6%、妻は約44.4%となり、拠出額は夫166,667円、妻133,333円。拠出後残額は夫333,333円、妻266,667円となる。

## 5. 入力・例外ケース案

- 金額は円単位の数値で入力し、0円未満は受け付けない。
- 夫婦のボーナス合計が0円の場合は、負担割合と拠出額を0円とする。目標額が0円より大きければ目標額を未拠出として示し、計算不能や資金不足が利用者に伝わる表示を検討する。
- 片方のボーナスだけが0円の場合、もう片方の負担割合を100%とする。
- 貯金目標額が0円の場合、拠出額は両者とも0円とする。
- ボーナス合計が貯金目標額を下回る場合も計算を続け、拠出後残額をマイナスで表示する。
- 負担割合は表示上小数第1位までとし、計算は入力金額から求めた丸め前の割合を使用する。
- 入力欄を空にした際の一時状態と、その場合の計算表示は実装時に既存ページの入力挙動と揃える。

## 6. 既存ページとの関係

- 月次の負担割合計算は現状どおりとし、ボーナス計算は別ページとして追加する。
- 月次計算で利用している CSV の共通予算や初期月収は、ボーナス計算には使用しない。
- 画面デザイン、通貨表示、ダークモード、負数の強調表示は既存ページに合わせる。
- ページ追加時には、ヘッダーのナビゲーション、関連するテスト、`docs/家計負担割合_仕様解説書.md` のページ説明を更新する。

## 7. 仕様確定時に確認する点

この資料では、ボーナス手取り額の比率を負担割合にする案を採用している。月次計算と同じ収入比率を使う運用も考えられるため、実装前に「ボーナス額の比率」と「月収の比率」のどちらを負担割合にするかを確定する。

また、貯金目標額を超えるボーナス合計の場合の残額表示、目標額がボーナス合計を超える場合の警告表示、および初期値は、実装時に画面設計と合わせて最終決定する。
